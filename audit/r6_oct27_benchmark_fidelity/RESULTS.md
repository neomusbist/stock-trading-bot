## 2. 최초 불일치: 입력과 WATCH 자격 단계

10/26 추출기는 사후 `breakouts`의 `is_watch`와 돌파 시각으로 21종목을 선택했다. 10/27 추출기도 20종목을 사전 나열했다. 각 종목이 당시 알려진 후보였는지, 실제 WATCH였는지 증명하는 이력이 캐시에서 빠졌다. 시뮬레이터는 모든 종목에 `WATCH`, `source_count=2`, 정상 시장 상태를 부여했다. 이것이 생산 경로와 가장 앞에서 확인되는 입력 계약 불일치다.

또한 수신·소비 시각, 누적 거래량, 독립 호가 시각·잔량, 구독 이력을 제거했다. 거래소 시각을 처리 시각으로 사용하므로 실제 지연과 신선도 검사를 재현하지 못한다. 10/26 캐시는 거래량 키가 `vol`인데 시뮬레이터는 `volume`만 읽어 121,140개 체결을 각각 1주로 처리했다. 그 날의 유동성 탈락과 0건 결과도 유효하지 않다.

따라서 ‘첫 판단 차이’를 특정 LIVE 주문 거절 하나로 환원할 수 없다. 실제 동일 수신 ID의 전 단계 WATCH·계좌 자료가 없는 구간의 정확한 최초 LIVE 판단은 UNKNOWN이다. 확인 가능한 순서는 **종목선정/WATCH 입력 → 워밍업·구조 설정 → 비용 RR → 실제 runner의 신선한 구조 재심사 → 주문/체결/청산**이다. 외부 시뮬레이터는 이 가운데 입력과 후반 경로를 대체했다.

5. 각 전략을 실제 `PatternDetector.signal()` 생성기로 격리하고 **실제 runner의 신선한 일봉/저항 재평가 → AutonomousEngine → 영속 INTENT → QuoteReplayBroker → cumulative_fill/reconcile → 실제 청산 엔진**으로 연결했다. 직접 broker.submit 호출이나 포지션 삽입·삭제로 통합 검사를 대신하지 않는다.
6. 완전한 설정 스냅샷·입력 해시·프로필 해시를 요구한다. WATCH 시각, 자료 공백, 중복 체결, 별도 0D 재평가를 구분한다. 원본 거래와 일치하지 않는 QUOTE_RETRY를 거절한다. 소스 기본값의 몰래 적용과 입력 파일 덮어쓰기를 차단한다.
7. 데이터 종료 시 진입가로 가상 강제청산하지 않는다. 미청산 포지션과 미체결은 그대로 결과에 남는다. 목표 도달도 생산 엔진이 정의한 별도 판단이며, 목표가 자동 전량매도로 바뀌지 않는다.

PAPER의 계좌·정규장 상태·승인은 명시적 임시 fixture다. 실제 일중 계좌/승인/REST/감독 프로세스까지 동일하다고 주장하지 않는다. 기본 모의 지연 25ms와 표시 L1 체결은 연구 가정이며, 주문 접수·체결을 보장하지 않는다.
