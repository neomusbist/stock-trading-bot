수신 이력은 순서대로 모두 수집한다. 기회 평가 대기 자료만 종목당 최신 1개로

주 큐 우선권을 유지한다. 주 큐 catch-up 뒤에는 별도 최대 2ms 예산으로
미뤄진 기회를 다시 본다. 두 예산은 **평가 시작을 제한하는 값**이며 이미 시작한
한 평가나 브로커 요청의 실제 실행시간을 보장하지 않는다. 컨트롤/주문/보유 틱은
별도 FIFO로 유지된다. 큐 누락 시 non-critical ABC와 FAST 예열을 함께 초기화한다.

새 매수 전략·익절 정책·고정 최소 보유시간·더 넓은 손절 비율을 추가하지 않았다.

   실험 전략 활성화나 임계값 변경은 이 승인 범위에 넣지 않는다.
2. 그 정확한 운영 후보에서 표적 검사·무결성 검사를 실행한다.
3. 사용자 배포 승인 후 공식 STOP, 증권사와 장부의 보유/미체결/UNKNOWN/
   처리 중 주문/HALT를 새로 대조한다. 포지션 보호가 필요한 동안 재시작하지 않는다.
4. 승인된 최소 파일을 백업·교체하고 해시/manifest를 다시 만든다.
   계좌·장부·일일 손실·위험예산·HARD_LOCK·승인 자료는 초기화하지 않는다.
5. 해당 BUILD의 기존 승인 절차로 재개한다. 승인 없이 주문 권한을 넓히지 않는다.

## 다음 세션의 측정 기준

- 실제 구독된 적격 종목의 RAW/첫 틱/WATCH/첫 고유 신호/PRE_INTENT/PRE_HTTP/
  제출/접수/체결을 각각 집계한다. 이벤트 반복을 독립 기회로 세지 않는다.
- 정상 수신한 legacy 신호가 관측 큐 때문에 주문 평가를 한 번도 받지 못하면 실패다.
  다만 계좌·스프레드·저항·비용·신선도 차단은 사유와 당시 값으로 따로 분류한다.
- 모든 실제 BUY는 수량×limit+비용이 당시 자금 안에 있고, 원래 트리거와 최종 호가가
  모두 유효해야 한다. 늦은 신호나 limit보다 비싼 ask가 통과하면 실패다.
- FAST HOLD가 임시 이익보호선의 공통 비상선 승격 때문에 뒤집히거나,
  진짜 비상선/데이터 장애 보호가 지연되면 실패다.
- 주 큐 지연, 관측 누락, API 호출 수, 관측→신호 평가 지연을 기존값과 비교한다.
  위 합성 검사는 저사양 PC의 실전 p95 지연 개선을 입증하지 않는다.
- 순손익·MFE 포착률·MAE·비용·재진입 결과를 함께 수집한다.
  단 하루의 거래 수 증가나 이익 한 건을 기대값 개선으로 판정하지 않는다.
