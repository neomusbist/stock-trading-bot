# KT00018 보존 관측 후보와 C2 PAPER 연구

## 결론

관측 후보는 현재 설치된 KT00018 릴리스의 실제 소스로 재작성했다. API 제한/재시도/백오프/계좌 불확실성/주문 재전송 금지 코드는 보존했다. LIVE에는 설치하지 않았다.

C2는 구현했지만 **실제 보존 표본에서 주문 적격 신호를 확인하지 못했다. LIVE NO-GO**다. 합성 양성 사례의 BUY·체결·보호 청산은 실행 경로 증거이며 수익성 또는 실시장 주문 가능성 증거가 아니다.

## A. 관측 후보

- 기준: `R6-KT00018-20261028-7d3c3d949105`, 개발 기준 `78188479ceaf0186963dba29fab69ccb5304e96d`.
- 후보: `R6-OBSERVE-KT-20261028-4bd344ffbb85`.
- 정확히 6파일: `automation/decisions.py`, `automation/engine.py`, `automation/runner.py`, `automation/trade_review_capture.py`, `automation/entry_evidence.py`, `runtime/RELEASE_IDENTITY.json`.
- `core/broker.py`/`core/balance_rate.py` 물리 해시 동일. 설치본 103개 전체 소스를 비교했다. 후보의 소스 식별 목록은 새 모듈을 포함해 104개다.
- 설치본 대비 engine의 변경 함수는 `event`뿐이다. runner는 `evaluate_actual_entry`, `record_order_readiness_transition`, `run`의 관측 연결만 변경했다. `run` 내부 금융 처리 함수들은 AST가 동일하다.
- A 저항 연구, 공통 RR 연구 변경, C2 가드/전략/청산 실험, D/E2 옵션은 이 후보에 포함하지 않았다. 개발 engine과 배포 후보 engine은 의도적으로 다르다.
- 같은 수신 체결의 WATCH→일봉 재검사 ELIGIBLE 상태를 구분하는 `entry_scope_status`를 보존한다. 다른 체결이나 SHADOW에 WATCH 자격을 전파하지 않는다.
- 기록은 기존 비동기·용량 제한·회전 기록기를 사용한다. 주문 원장을 대체하지 않으며 누락은 UNKNOWN이다. 새 관측 후보의 실제 개장 CPU/큐 영향은 미검증이다.

### 계좌 조회 15초 초과의 잔여 위험

완전한 최신 계좌 조회가 없으면 신규매수는 차단된다. 과거 현금·보유수량을 0으로 바꾸지 않는다. 체결/미체결 조회 경로는 잔고 TR 실패와 분리되어 있다.

그러나 **기존 최종 가드는 계좌가 15초 넘게 오래되면 보호 매도 전송도 차단한다.** 청산 요청과 마지막 검증 수량은 영속 원장에 보존된다. 완전한 계좌 재대조와 신선한 호가가 복구되면 기존 보호가 재개되는 것을 실제 설치 소스 복제본에서 확인했다.

조회 불능 중에도 반드시 보호 주문을 보낼 수 있다고 주장하지 않는다. 오래된 매도 가능 수량을 유효하다고 간주하는 우회는 만들지 않았다. 관측 패키지가 이 기존 금융 제약을 해결한 것은 아니다.

## B. 기존 C와 C2

기존 C 코드는 변경하지 않았다. 최대 폭 1.5%, 목표 최대 `top + 2 * width`, 진입 `>= top`, 비상선 `<= low`를 공통 연구 비용 모델에 넣으면 최선의 순RR 상한은 **1.004645747741495**다. 실제 버퍼·잡음·돌파 초과가격을 생략해 유리하게 계산한 상한이며 요구 1.5보다 낮다.

정규화 예: low=10,000 / top=10,150 / target=10,450 / stop=10,000. 매수 수수료 0.015%, 매도 수수료 0.015%, 세금 0.2%, 진입 슬리피지 예약 0.2%, 청산 예약 0.3%. 예약은 실제 수수료나 지정가 초과 체결이 아니다. 이 수치는 해당 비용/박스 전제의 상한이며 과거 LIVE의 legacy RR 판정을 공통 모델 판정으로 바꾸어 부르지 않는다.

C2의 단일 가설은 **사전 확인 저항이 있는 박스 → 실제 돌파(여기서는 매수하지 않음) → 별도의 완성봉 지지 재확인 → 그 봉 고가 위의 실제 체결·ask**다. 목표는 박스 배수가 아니라 돌파 전에 확인된 가장 가까운 고점이며 이후 낮출 수만 있다. 구조선은 확인된 재시험 저가의 한 틱 아래, 비상선은 여기에 사전 관측된 범위/스프레드 잡음을 더 반영한다. RR 통과를 위해 선을 좁히지 않는다.

실제 `PatternDetector`의 적재/연속성/기본 게이트와 production runner·`AutonomousEngine`·영속 INTENT·`QuoteReplayBroker`·청산 엔진을 사용한다. C는 엔진 전달 태그이고 별도 `research_strategy=C2`가 식별한다. 진입·submit·최종 HTTP 경계에서 임시 PAPER 정책과 정확한 FakeBroker 유형을 요구한다. 단순 PAPER 플래그만으로 실브로커를 허용하지 않는다.

표의 에피소드는 독립 거래가 아니다. stage 플래그 false/건수 0은 해당 단계의 성립을 관측하지 못했다는 뜻이며, 미평가된 손절·가격구간이 불가능함을 입증하지 않는다. 반복 평가/quote retry/전이 로그 수를 거래기회 수로 합산하지 않았다.

- 10/26 `010170` 09:15:02.024738: 박스 13,330~13,520, 당시 확인 저항 13,530. 보상 여유 10원인 저항을 13,550 또는 더 먼 목표로 바꾸지 않았다. 재시험 구조는 확인되지 않았다.
- 10/27 `328130` 09:26:02.184949: 박스 14,700~14,850, 사전 확인 저항 15,300. 돌파 관측 후 별도 완성봉 지지 재시험이 확인되지 않았다. 이를 사후 저가 매수로 대체하지 않았다.
- 10/27 연속 표본의 공유 기록기 손실 카운터가 39,822 증가했다. 어느 종목/시간의 손실인지 확정할 수 없다. 네오셈 테이프 시작 손실 카운터 42,707과 중복 가능한 값이므로 합산하지 않는다.
- 수신층 행과 처리층 행이 함께 존재한다. `TRADE_PROCESSING_OR_RECEIPT_UNKNOWN` 행 수는 패킷 유실 수가 아니다. 처리 시각이 증명된 행만 재생했다.
- 과거 최종 계좌/권한 증거는 legacy 상세 표본뿐인 구간에서 UNKNOWN이다. 현재 70,420원 PAPER 초기 현금을 과거 실제 계좌로 간주하지 않았다.
- 확인한 LIVE trade-review 위치에는 10/15 연속 체결·호가 파일이 없다. 다른 곳에 전혀 없다고 단정하거나 가상 틱으로 채우지 않았다.
- 10/15·26·27은 개발 자료다. 미관측 성과 표본이 아니며 실제 진입이 없으므로 실제 MFE/MAE·기대값은 추정하지 않는다.

## 청산 실험

동일 진입에서 기존 정책/초기 구조선/1R 후 비용 본전/확정 저점 추적을 분리 구현했다. 기본 정책은 유지한다. 1R은 진입가와 최초 비상선의 가격 차이이며 계좌 2%가 아니다. 저점 추적은 오른쪽 완성봉이 나온 뒤에만 갱신하며 보호선을 내리지 않는다.

합성 양성 사례는 10,050원, 구조선 9,990원, 비상선 9,910원, 사전 저항 10,500원, 6주다. 실제 엔진의 모의 매수 이후 MFE 350원/주가 있었지만 다음 갭에서 네 정책 모두 비용 후 -1,156.497원으로 끝났다. 보호선 가격으로 허구 체결하지 않았다는 반례이지 네 정책의 성과 비교 표본이 아니다. 실데이터 주문 적격 진입이 없으므로 실데이터 paired exit 결과는 NOT_ESTIMABLE이며 청산 개선을 채택하지 않는다.

## 검증 및 판정

- 개발 관련 182 PASS; 전체 저장소 전수검사는 아니다.
- 실제 설치 소스 복제본 API/인증 26 PASS; 실제 설정 복사본 A/B 합성 주문 의도 2경로 및 계좌 15초 초과/복구 검증.
- 설치/롤백 11 PASS, 새 모듈 생성·제거/파일 오염/설정·장부 보존/적용 승인 차단 포함.
- Windows의 제한 장치 시계 해상도 15.625ms와 관측 QPC 0.1µs 차이로 0.55초 간격의 1ms 정밀도 검사가 한 차례 실패했다. 시험의 간격 오차만 측정 해상도로 보정했다. **실제 1초 이동창 최대 2회 검사는 그대로 엄격히 유지**했으며 API 구현은 바꾸지 않았다.
- LIVE 미설치·미기동·무주문. 원래 설정/장부/승인/소스 해시 보존.

관측 후보는 별도 승인 후 설치 가능한 연구 납품물이다. C2는 추가 실수신 검증용 PAPER 코드이며 LIVE 활성화는 NO-GO다. 기존 매수 불능과 수익성 문제가 해결됐다고 판정하지 않는다.
