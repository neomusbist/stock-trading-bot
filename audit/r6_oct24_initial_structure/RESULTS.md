# 독립 초기 진입구조 연구

기준 커밋: `25f03bea908869d630230aecc213aee5515e15ab`. 기존 A/B·ABRR·이전 두 대안은 그대로 보존했다. 이번 세 파일은 생산 runner에서 import하지 않는 오프라인 연구다. Windows R6-OBSERVE-20261026-4347e3081a27은 별도 설치하지 않고 STOP을 유지한다.

## 판정

새로운 LIVE 활성화 후보는 없다. 실제 주문 가능성이 검증된 추가 신호는 **0**이다. 그러나 같은 필터를 반복 수정한 결과도 아니다. 다음 순서로 독립 정의를 구현하고 실제 개별 수신 체결에서 판정했다.

1. **초기 3봉 돌파 A 가설:** 최근 연속 실수신 완성봉 3개의 높아지는 지지와 작은 구조 돌파를 사용한다. 그 구조 위의 당시 알려진 가장 가까운 미돌파 저항을 목표로 먼저 정하고, 지역 지지·기존 구조 버퍼·관측 잡음으로 구조선과 비상선을 정한다. 돌파 첫 가능 가격에서 공통 순RR 1.5가 성립하지 않으면 트리거를 기다리지 않는다. **경제성을 계산한 96개 구조 ID 모두 돌파 전 가격구간이 비어 있었다. 이 3봉/분봉잡음 정의를 이 표본에서 기각한다.** 별도 46개 참조 상태 키는 독립적인 위쪽 저항을 확인하지 못해 UNKNOWN이다. 먼 목표를 선택하지 않았다.
2. **초기 지지 회복 B 가설 v1:** 완성 회복봉의 고점 재돌파를 기다리지 않는다. 기존 상승 파동의 알려진 꼭짓점 아래에서 새로 닫힌 눌림 저점을 확인하고, 그 봉 이후 실제 체결 3개의 하락→이전 가격 회복과 신선한 매수호가 개선을 요구한다. 체결 방향은 관측되지만 공격적 매수체결량은 UNKNOWN이다. 목표는 미리 알려진 파동 고점이고, 구조선은 새 눌림 저점이다. **4개 구조 ID가 형성됐으나 모두 분봉 범위 기반 비상선을 적용하면 순RR 미달이다. 이 비상선 조합을 주문 가능한 설계로 채택하지 않는다.**
3. **같은 B의 잡음 시간축 가설 v2:** 목표·구조선·회복 트리거는 v1과 같다. 회복 시작 체결 이전 60초에 실제 관측한 최대 인접 체결 가격 변화, 각 체결 시점 유효 호가 간격, 최소 틱 중 최대값을 비상 잡음으로 비교한다. 유효 구간 55초 이상, 체결 인지시각 간 공백 5초 이하, 각 체결 시점 신선한 호가를 요구한다. 미래 자료·보간·RR에 맞춘 배수를 사용하지 않는다. **v1의 네 사례 중 2개는 필요한 체결별 유효 호가 이력이 불명확하고, 2개는 최대 수신 간격 7.252초로 이 가설의 연속성 조건을 충족하지 못했다. 비상선·경제 구간·주문수량은 UNKNOWN이다.** 이 모델은 검증 가능한 비활성 코드로 남겼으며 LIVE 후보가 아니다.

v2의 최대 한 번 가격 변화는 향후 정상 변동성의 예측치가 아니다. 누적 하락·복수 점프·완성봉 청산 지연을 감당하는지 아직 검증되지 않았다. 과거 분봉 범위보다 좁을 수도 넓을 수도 있다. 결과에 맞춰 구조선을 좁힌 것이 아니며, 이 잡음 가설을 수용하려면 다음 연속 자료에서 잡음 초과·구조 실패·비상선 접촉을 별도 검증해야 한다.

실패한 설계 가정도 분리했다. A 96개에서 첫 돌파 가능 가격 기준 목표 여유 중앙값은 0.210%, 구조선 거리 1.077%이며, 비용을 0으로 놓고 구조선만 사용해도 RR 1.5 이상은 7개뿐이었다. 74개는 원래 비용·슬리피지에서 목표 도달 보상 자체가 0 이하였다. 단순히 완성봉을 3개로 줄이면 가까운 저항과 위험거리 충돌이 해결된다는 가정은 지지되지 않았다. 반면 새 B 네 구조는 같은 첫 가능 가격에서 비용 0·구조선 기준 RR 1.5를 모두 통과하지만, 3봉 범위 비상선을 포함하면 모두 통과하지 못했다. 새 B는 이전 B와 같은 문제를 무조건 반복한 것이 아니라 **회복 시점의 구조 여유와 잡음 시간축을 분리할 수 있는 정의**다. 비용 0 계산은 원인 분해용이며 승인 수량·주문 신호로 세지 않는다. 기존 A94/B26과 새 구조 96/4는 같은 표본·지문이 아니다.

## 구현·안전·검증

- `research/initial_structure.py`: 기존 A/B와 독립된 가격구조→목표→구조선/잡음→경제 구간→실제 돌파→호가→공통 수량 경로. 원래 연구 신호는 항상 SHADOW_ONLY/actual_order_permission=false다.
- `research/support_recovery.py`: 순차 B 가설과 명시적 잡음 비교 옵션. 체결 인지시각과 나중에 도착한 호가 인지시각을 분리한다. 실제 구독 해제/연결 단절/기록 손실은 상태를 무효화한다. WATCH 랭킹 변경만으로 실수신 이력을 만들거나 지우지 않는다.
- `research/initial_structure_replay.py`: 수신 가용 시각순으로 개별 실제 적재 체결과 알려진 BOOK을 평가한다. BOOK 수신 시각의 반사실 연구 평가를 실제 LIVE 소비 시각으로 보고하지 않는다. OPPORTUNITY_SAMPLE은 정확히 일치하는 실제 체결의 자격만 보완하며 체결을 만들지 않는다. 미래 REST/봉을 미리 사용하지 않는다. 출력은 새 외부 위치만 허용하고 네트워크를 차단한다.
- 구조 경제성의 첫 돌파 가능 틱은 아직 실제 ask가 아닌 계산용 probe로 명시한다. 실제 신호에서는 수신 ask로 다시 공통 계산한다. 초안에서 두 값의 라벨이 같았던 연구 결과 출처 오류를 1 FAIL→PASS로 고쳤다. 계산식·목표·손절·신호 수 변경은 없다.
- 원래 SHADOW 신호는 생산 엔진에 주문할 수 없다. 명시적 `--paper`는 기존의 임시 디렉터리·타입 제한 브로커만 사용한다. 정확한 WATCH 자격 표본과 신선한 호가가 있는 경우에만 연결한다. 실제 계좌 승인·REST·금융권한을 변경하지 않는다. 실제 입력의 세 가설 모두 PAPER 주문 의도까지 도달한 사례가 없었다.
- 관련 **137개 고유 검사 PASS, 실패/오류/생략 0**. 신규 모델·인과적 잡음·가용시각·REST 워밍업 금지·목표/구조선 고정, 기존 비용 통일·A/B 대안·수신 연결·PAPER 원장/보호·위험2%/일일4%·승인 및 HARD_LOCK을 검사했다. 전체 저장소 전수검사는 아니다. 테스트 소스 해시도 고정했다.
- 합성 A/B 양성 자료에서는 기존 엔진의 주문 의도→모의 접수/체결→비상 보호청산 경로가 통과했다. 이는 실제 시장 신호나 실제 체결의 증거가 아니다. 합성 fill provenance를 그대로 보존한다.
- 최종 봉인 소스의 오프라인 처리: A CPU58.281초/경과59.756초, B v1 CPU40.672초/경과43.597초, B v2 CPU38.750초/경과39.208초. 같은 컴퓨터에서도 개장 큐·실전 지연·실시간 처리 상한을 입증하지 않는다. 생산 루프 평가 추가 부하는 0이며, 연구 재생은 장중 LIVE와 동시 고부하 실행하지 않는다. 세 모드 모두 같은 입력 SHA·최종 소스 SHA로 다시 확인했고 테스트 소스 SHA와 일치한다.
- 실제 추가 신호가 없어 거래별 MFE/MAE·비용 후 실현손익·거짓 신호 증가·기대값은 산출하지 않았다. UNKNOWN을 0원 수익으로 처리하지 않는다. 향후 신호가 있으면 관측된 이후 체결과 30/60/180초 신선한 L1 청산 가정만 별도 표시하며, 마지막 봉으로 강제 청산하지 않는다.

확장 회귀 검사에서는 테스트 캡슐에 기존 local_breakout 의존 파일이 없어 import 오류가 있었다. 또한 기존 캡슐의 observation_worker가 연구본과 달라 소스를 맞췄을 때, 캡슐 자체의 오래된 파일 해시가 11개 안전 검사를 차단했다. 연구 소스와 동일한 임시 캡슐만 별도 OFFLINE 식별자로 봉인한 후 최종 137개를 통과했다. 생산 manifest나 안전 검사를 완화하지 않았다. 이 테스트 환경 오류를 LIVE 결함이나 해결된 매매 장애로 세지 않았다.

## 다음 실수신 입력의 비교 명령

기존 검증된 동결 절차로 생성한 MANIFEST와 실제 config/automation이 있는 입력만 받는다. `$r6Freeze`와 각 출력 경로는 운영 폴더 밖 새 위치다. 전략별 출력은 분리한다. 실제 잔고를 모르면 시나리오 현금을 생략해 수량 UNKNOWN으로 유지한다.

```powershell
python -B -m research.initial_structure_replay --hypothesis A --freeze "$r6Freeze" --output "$r6OutA"
python -B -m research.initial_structure_replay --hypothesis B --freeze "$r6Freeze" --output "$r6OutB"
python -B -m research.initial_structure_replay --hypothesis B_PREFIX --freeze "$r6Freeze" --output "$r6OutPrefix"
```

명시적 가용 현금 시나리오를 비교하려면 `--scenario-cash`를 지정한다. `--paper`는 그 시나리오에서만 허용한다. 실제 당시 장부가 없으면 실제 계좌 주문 가능성은 UNKNOWN이다. 기존 네 경로는 `research.session_validation`으로 같은 동결 입력에서 비교하며, 새 경로를 생산 runner에 설치하지 않는다.

RESULT의 structure_id/source_id/receipt와 first_structure_at/trigger_at/first_L1_at를 연결한다. plan에는 목표 근거와 known_at, 구조선·잡음 근거, 최대 허용가가 들어간다. unresolved_noise_candidates는 네 사례처럼 비상선 산정이 불가능한 이유와 당시 quote를 남긴다. 이후에야 실제 WATCH 자격·호가·위험잔액·수량을 확인해 PAPER 단계로 넘긴다. 구조 ID 수를 체결 수로 세지 않는다.

## 보존 및 롤백

이 변경은 연구 소스 3개, 테스트 3개, 문서/건별 CSV 및 업로드 허용 목록뿐이다. 생산 금융 코드와 설정은 변경하지 않았다. private 원본·계좌/장부·SQLite·로그·합성 fill 원본은 업로드하지 않는다. 실행 당시 A/B v1 소스 snapshot과 각 RESULT/SUMMARY, 마지막 v2 최종 소스 SHA, 테스트 결과를 외부 작업 폴더에 보존했다.

연구 롤백은 이 커밋을 정상 revert하는 방법이며 LIVE·장부·설치 RELEASE를 되돌릴 작업이 없다. 신규 전략을 운영 활성화할 승인 요청은 제출하지 않는다. 다음 관측에서 실제 실행 가능 사례와 잡음 모델의 실패율이 검증되기 전에는 LIVE 후보가 아니다.
