## 새로 고친 기술적 문제

- 기존 장전 점검은 최신 heartbeat/연결만 있으면 소스 해시 변경을 놓칠 수 있었다. 이제 실제 manifest 파일 해시, 예상 RELEASE, 읽기 실패, 작업 PID, STOP, 당일 승인 날짜와 기존 readiness 차단을 따로 표시한다. 날짜 일치는 최종 금융 승인 검증을 대신하지 않는다. GUI 인증은 사용자 확인 대상이다.
- 이전 네 경로 재생은 특정 과거 로컬 파일에 묶여 있었다. `research.session_validation`은 검증된 동결 manifest를 직접 받고, 입력을 SQLite에서 실제 가용 시각으로 정렬한 뒤 기존 탐지기를 순차 실행한다. 전략·목표·손절·RR 계산을 새로 만들지 않는다.
- WATCH 역할 해제만으로 관측을 지우지 않는다. 실제 `SUBSCRIPTION_SCOPE.removed`/연결 단절/기록 손실은 별도 공백이다. 저장봉·유효봉·관찰 시작·warmup 상태가 바뀔 때만 EVALUATION_STATE를 남겨 0/70초 재시작을 구별한다.
- 새 재생기 자체의 첫 시험에서 정상 REG ACK를 단절로 오인한 오류를 발견해 고쳤다. 이는 LIVE 결함 수정 주장이 아니다. REG ACK 보존 회귀검사를 추가했다.
- 기존 생산기 완성봉과 재구성한 동일 분 봉은 하나로 합친다. REST는 당시 알려진 참조로만 쓰며 체결 워밍업을 대체하지 않는다.
- RAW 최초 인지는 캐시 first_raw_at이 아닌 기존 RAW_CANDIDATES 저널의 실제 인지 시각으로 연결한다. 상세 샘플은 전수 평가가 아니다.
- BOOK 수신 시각만으로 전략 소비 시각을 만들지 않는다. 기존 ENTRY_QUOTE_RETRY가 있을 때 실제 trade_received_at/book_received_at와 원본 BOOK을 연결한다. 이 연결이 없는 0D 단독 최초 평가 시점은 UNKNOWN이다. 추가 LIVE 로깅 배포 없이 가능한 기존 증거를 재사용했다.

## 경제적 충돌의 추가 분해와 가설 우선순위

새 목표를 만들지 않고 같은 확인 구조·같은 실제 ask에서 건별로 비교했다. 비용을 모두 빼고 구조선만 위험으로 보아도 RR 1.5 이상은 A 94개 중 5개, B 26개 중 0개였다. 비상선까지 포함하면 A 1개/B 0개였다. 즉 A 89개와 B 26개는 수수료나 비상 노이즈 폭을 제거하는 것으로 해결되지 않는다. 이것은 안전장치를 제거하자는 제안이 아니다.

구조선 기준 비용 전 RR 중앙값은 A 0.321/B 0.183, 비상선 기준은 A 0.269/B 0.118이다. 이는 실제 ask 기준의 건별 RR 분포이며 앞서 최소 트리거 가격으로 계산한 분포와 다르다. 목표가가 ask 이하인 A 11/B 9, 트리거 이하인 B 15도 그대로다. RR 1.5에 필요한 보상 부족분을 각 진입가로 나눈 중앙값은 A 3.724%p/B 2.420%p다. 목표를 그만큼 올리라는 의미가 아니다.

1. **우선 확인: 진입 구조와 시간축의 불일치.** A는 최근 2~4봉의 작은 투영과 최대 120봉 참조에서 찾은 지지/노이즈 비상선을 함께 쓴다. B는 12봉 이내의 전고점 목표에 완성 회복봉과 재돌파를 요구한다. 이 조합의 충돌은 코드와 첫 확인 가격으로 확인됐지만 더 이른 주문 가능 구간의 존재는 입증되지 않았다.
2. **A 조기 돌파 가설:** 당시 확정된 구조·저항이 있는 최초 돌파에서 기존 방식과 A 재확인 대안의 시각/허용가를 비교한다. 먼 저항을 새로 만들거나 구조 지지를 현재가에 맞춰 좁히지 않는다. 더 이른 저위험 구조가 관측됐는지가 판정 기준이다.
3. **B 이른 지지 회복 가설:** 전고점 상한을 유지한 채 기존 B와 이미 구현된 지지 회복 대안을 비교한다. 이 대안의 현재 실수신 추가 신호도 0이므로 새 트리거를 또 추가하지 않는다. 연속 자료에서도 보상 구간이 거의 없으면 기존 정의의 재설계/폐기를 검토한다.
4. **더 긴 보유 시간축 가설:** 초단기 보상 폭보다 구조 위험이 큰 자료는 연구 필요성을 지지하지만, 익일 갭·보유 위험·비용 후 기대값은 이 자료로 판정할 수 없다. 짧은 스윙 전환은 비활성 가설이며 구현·활성화하지 않는다.

종목 선정의 잘못 여부는 판단 보류다. 최초 RAW 시점의 실제 ask/당시 알려진 저항과 첫 구조 시점이 짝지어진 자료가 충분하지 않다. 사후 상승으로 최초 상승 여력을 만들지 않는다. 월요일에는 그 짝이 있는 경우만 여유 소진을 계산한다.

## 실행 명령

프로젝트 루트에서 아래 변수에 **운영 폴더와 운영 폴더 밖의 새 출력 위치**를 지정한다. 조회는 시작/주문/설정을 수행하지 않는다.

```powershell
python -B -m research.evidence_collector --check-only --day 2026-10-26 --expected-release R6-OBSERVE-20261026-4347e3081a27 --source-root "$r6LiveRoot" --output "$r6StatusFile"
python -B -m research.evidence_collector --freeze-preopen --day 2026-10-26 --source-root "$r6LiveRoot" --output "$r6PreopenRoot"
```

장전 동결은 대상 거래일 08:00~09:00만 허용한다. 실제 GUI/키움 인증·당일 승인·정상 시작은 사용자 절차다. 08:55까지 최신 작업/수신 기록이 없으면 준비 완료가 아니다. 장전에는 정규장 체결이 아직 없을 수 있으므로 당일 승인, 수신 준비, 정규장 주문 가능 상태를 따로 판단한다.

정규장 종료 후 여유 시간에 저우선순위로 정확한 바이트와 SHA를 보존한다. 원본을 지우거나 이동하지 않는다. 공간 부족으로 32GiB 여유를 지킬 수 없으면 거부한다.

```powershell
python -B -m research.evidence_collector --freeze-session --day 2026-10-26 --source-root "$r6LiveRoot" --output "$r6SessionRoot"
python -B -m research.evidence_collector --audit-freeze --source-root "$r6SessionRoot" --output "$r6AuditFile"
python -B -m research.session_validation --freeze "$r6SessionRoot" --preopen "$r6PreopenRoot" --output "$r6ReplayRoot" --session REGULAR --evaluations received
```

각 출력은 새 위치여야 한다. 재생은 입력/출력 겹침과 덮어쓰기를 거부한다. 완전한 MANIFEST가 없으면 동결 완료가 아니고, SUMMARY가 없으면 재생 완료가 아니다. 기본 상세표본 비교는 `--evaluations samples`다. received 모드는 실제 전략 적재 체결, 당시 WATCH 자격, 연결 가능한 실제 호가 재시도에서 재평가한다. 역할 자료가 없으면 평가하지 않는다. 수신 큐 지연을 없앤 반사실로 실전 최초 시각을 확정하지 않는다.

네 variant는 baseline, a_retest, b_reclaim, ab_rework이며 기존 A/B와 두 연구 대안을 독립 토글한다. baseline도 현재 연구 ABRR 코드이며 설치된 구형 금융 코드와 동일하다는 뜻이 아니다. 모든 연구 대안은 LIVE 주문 OFF다. 네 탐지기를 운영 루프에 넣지 않는다.

장전 파일이 없거나 날짜/설정이 다르거나 계좌가 무보유·해결 상태가 아니면 실제 계좌에 대응하는 수량을 만들지 않는다. 검증된 장전 상태가 있어도 기존 PAPER 엔진의 가정된 브로커/정규장 모델이지 실제 당일 금융 승인·접수 증거가 아니다. 수신 호가가 있어도 실제 주문 접수·체결과 구분한다. 미체결/진입 없음에서 MFE·MAE·기대값을 만들지 않는다.

오프라인 예산 상한은 3,000,000행/구조 200,000지문이며 초과하면 완료 결과를 거부한다. 전체 월요일 파일의 메모리/시간은 아직 미검증이다. 자료는 세션/구간을 명시해 분할할 수 있으나 각 분할의 장전 자금을 새로 리셋해 하루 성과로 합산하지 않는다.
